\section{Introducción}

En la era moderna del desarrollo de software, la velocidad de entrega y la confiabilidad del sistema se han convertido en pilares fundamentales para el éxito empresarial y la sostenibilidad técnica de cualquier infraestructura digital. Tradicionalmente, la transición entre la etapa de desarrollo y la fase de producción implicaba procesos manuales propensos a errores humanos, inconsistencias en los entornos de ejecución, y tiempos prolongados de inactividad (\emph{downtime}) que afectaban negativamente la experiencia de los usuarios finales. Como respuesta a esta problemática, la filosofía DevOps ha introducido metodologías centradas en la automatización continua, destacando la Integración Continua (\emph{Continuous Integration} - CI) y el Despliegue Continuo (\emph{Continuous Deployment} - CD).

Estas prácticas garantizan que cada modificación realizada en la base de código sea validada exhaustivamente mediante baterías de pruebas unitarias y de integración de forma automática, asegurando que únicamente las versiones verificadas sean empaquetadas de forma homogénea y desplegadas en la nube. La tecnología de contenedorización impulsada por Docker juega un rol vital al empaquetar la aplicación junto con sus dependencias y configuraciones en un elemento estandarizado e inmutable. Esto elimina por completo el clásico dilema de «funciona en mi máquina local», garantizando que el comportamiento observado en el entorno de desarrollo coincida de manera exacta con el comportamiento en servidores de producción como Amazon Web Services (AWS EC2).

El presente reporte documenta la implementación práctica e integral del ciclo de vida continuo para una aplicación web desarrollada en Node.js y Express. La aplicación desarrollada expone una API REST HTTP en el puerto 80 para el manejo de categorías y productos con persistencia en SQLite, integrando además un servidor de Socket TCP nativo en el puerto 6061 que comparte la misma base de datos. A lo largo de esta práctica se aborda el desarrollo del backend, la creación de pruebas unitarias e integración con Jest y Supertest (garantizando un umbral de cobertura superior al 70\%), la creación de un Dockerfile optimizado, la orquestación del pipeline de CI/CD mediante GitHub Actions y el despliegue automático y seguro sobre una instancia virtual Ubuntu Server en AWS EC2.

Adicionalmente, se enfatiza la importancia de la seguridad en la infraestructura en la nube mediante la gestión de secretos criptográficos (GitHub Secrets), evitando la exposición pública de credenciales, claves SSH o tokens de acceso. La integración sinérgica entre la contenedorización, la verificación automatizada de calidad de código y la automatización de despliegues permite evidenciar cómo una arquitectura web puede evolucionar e implementarse de forma transparente y sin tiempo de inactividad frente a los requerimientos de la ingeniería de software actual.

\section{Desarrollo y Resultados de la Práctica}

\subsection{Desarrollo del Backend y Protocolos HTTP/TCP}
Se construyó un servidor en Node.js ([`index.js`](file:///c:/Users/pokes/webapp-api/index.js)) que expone dos capas de comunicación compartiendo un motor de base de datos relacional ligero SQLite ([`database.js`](file:///c:/Users/pokes/webapp-api/database.js)):

\begin{enumerate}
    \item \textbf{API REST HTTP (Puerto 80):} Expone endpoints para operaciones CRUD sobre categorías y productos con cláusulas \texttt{JOIN}, el endpoint de verificación de salud \texttt{GET /api/health}, copia de seguridad \texttt{POST /db/backup} y limpieza \texttt{DELETE /db/truncate}.
    \item \textbf{Servidor Socket TCP (Puerto 6061):} Implementado con el módulo nativo \texttt{net} de Node.js. Procesa mensajes en formato JSON estructurados bajo las llaves \texttt{\{"insert": ...\}} y \texttt{\{"get": ...\}}.
\end{enumerate}

\begin{lstlisting}[language=JavaScript, caption=Implementación del Servidor HTTP y Socket TCP (index.js)]
// Endpoint de Health Check
app.get('/api/health', (req, res) => {
  sendResponse(res, 200, { status: 'UP', timestamp: new Date().toISOString() });
});

// Protocolo Socket TCP en el puerto 6061
const tcpServer = net.createServer((socket) => {
  socket.on('data', (chunk) => {
    const payload = JSON.parse(chunk.toString().trim());
    if (payload.insert) { /* Logica de insercion en SQLite */ }
    else if (payload.get) { /* Logica de consulta con JOIN */ }
  });
});
\end{lstlisting}

\subsection{Pruebas Automatizadas y Cobertura de Código (Jest \& Supertest)}

\begin{lstlisting}[language=JavaScript, caption=Fragmento de las Pruebas de Integracion (tests/api.test.js)]

\subsection{Contenedorización con Docker}
Se redactó un \texttt{Dockerfile} utilizando la imagen base oficial \texttt{node:18-alpine} y exponiendo explícitamente ambos puertos requeridos (80 y 6061). Asimismo, se configuró \texttt{.dockerignore} para optimizar el tamaño de la imagen final.

\begin{lstlisting}[language=SQL, caption=Dockerfile de la aplicacion]
FROM node:18-alpine
WORKDIR /usr/src/app
COPY package*.json ./
RUN npm install --production
COPY . .
EXPOSE 80
EXPOSE 6061
CMD ["node", "index.js"]
\end{lstlisting}

\subsection{Pipeline de Integración y Despliegue Continuo (GitHub Actions)}
Se estructuró el flujo de trabajo automatizado en \texttt{.github/workflows/main.yml}. El pipeline ejecuta automáticamente tres trabajos (\emph{jobs}) secuenciales ante eventos \texttt{push} en la rama \texttt{main}:

\begin{enumerate}
    \item \textbf{Run Tests and Code Coverage:} Ejecuta las pruebas automatizadas y valida que la cobertura supere el 70\%.
    \item \textbf{Build and Push Docker Image:} Autentica de forma segura en Docker Hub utilizando un Personal Access Token (PAT) y sube la imagen etiquetada como \texttt{latest} y con el hash SHA del commit (\texttt{santimtz23/webapp}).
    \item \textbf{Deploy to AWS EC2:} Conecta mediante SSH a la instancia AWS EC2 (\texttt{3.23.64.95}), descarga la versión reciente desde Docker Hub, detiene el contenedor previo y levanta la nueva versión exponiendo los puertos 80 y 6061.
\end{enumerate}

En la Figura \ref{fig:github_actions_success} se ilustra la ejecución exitosa de la canalización de CI/CD completa registrada en la consola de GitHub Actions.

\begin{figure}[H]
    \centering
    \includegraphics[width=0.95\linewidth]{pipeline_success.png}
    \caption{Ejecución exitosa del Pipeline CI/CD en GitHub Actions finalizada en verde.}
    \label{fig:github_actions_success}
\end{figure}

\begin{lstlisting}[language=SQL, caption=Fragmento del Workflow CI/CD (.github/workflows/main.yml)]
name: CI/CD Pipeline
on:
  push:
    branches: [ main ]
jobs:
  test:
    name: Run Tests and Code Coverage
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: '18' }
      - run: npm install --include=dev
      - run: npm test

  build-and-push:
    needs: test
    runs-on: ubuntu-latest
    steps:
      - uses: docker/login-action@v3
        with:
          username: ${{ secrets.DOCKER_HUB_USERNAME }}
          password: ${{ secrets.DOCKER_HUB_TOKEN }}
      - uses: docker/build-push-action@v5
        with:
          push: true
          tags: ${{ secrets.DOCKER_HUB_USERNAME }}/webapp:latest

  deploy:
    needs: build-and-push
    runs-on: ubuntu-latest
    steps:
      - uses: appleboy/ssh-action@v1.0.3
        with:
          host: ${{ secrets.EC2_HOST }}
          username: ${{ secrets.EC2_USERNAME }}
          key: ${{ secrets.EC2_SSH_KEY }}
          script: |
            sudo docker pull ${{ secrets.DOCKER_HUB_USERNAME }}/webapp:latest
            sudo docker stop webapp-prod || true
            sudo docker rm webapp-prod || true
            sudo docker run -d --name webapp-prod -p 80:80 -p 6061:6061 --restart always ${{ secrets.DOCKER_HUB_USERNAME }}/webapp:latest
\end{lstlisting}

\subsection{Verificación y Validación del Despliegue en Vivo}
El funcionamiento continuo y automatizado del pipeline puede ser comprobado directamente en la consola de GitHub Actions y mediante la consulta de los endpoints públicos. Al realizar cualquier modificación en la base de código del repositorio y enviarla a la rama principal, la canalización de CI/CD ejecuta secuencialmente la validación de pruebas unitarias, el empaquetado del contenedor y la actualización del servidor en la nube AWS EC2.

\section{Conclusiones}

La realización de esta práctica ha permitido constatar de manera directa la eficacia y robustez que ofrece un pipeline de Integración y Despliegue Continuo (CI/CD) automatizado en el ciclo de vida del software. La integración de herramientas de prueba como Jest y Supertest dentro del flujo de GitHub Actions garantiza que ningún cambio defectuoso o que no cumpla con el umbral mínimo de cobertura del 70\% pueda avanzar hacia la etapa de empaquetado. Esto minimiza drásticamente la probabilidad de regresiones en producción y eleva la calidad técnica global del sistema.

Asimismo, la contenedorización mediante Docker y el despliegue automático hacia la infraestructura en la nube de AWS EC2 demostraron cómo es posible actualizar un servicio en producción de forma rápida y sin tiempo de inactividad. La gestión centralizada de llaves y credenciales mediante GitHub Secrets reafirma la importancia de las mejores prácticas de ciberseguridad, asegurando un entorno protegido y profesional. En conclusión, la automatización de extremo a extremo desde el commit local hasta el servidor remoto brinda una base sólida para el desarrollo acelerado de aplicaciones web modernas.
